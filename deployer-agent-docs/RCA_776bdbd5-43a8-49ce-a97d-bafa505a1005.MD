## How each answer was obtained (evidence)

### 1. Which DB does the RUNNING production pod use?
Resolved server-side from the **live run's own `MONGO_URL` / `DB_NAME`** (the same env the running pod process reads) via the read-only mongo tool. Resolved `db_name` returned: **`greeting-app-5782-test_database`**.
- Cluster identity (leaks nothing): **Emergent-managed MongoDB Atlas (production)** — a managed cluster distinct from the preview source-pod's local `mongod`. The backend compute runs on K8s cluster `target-13`; the data store is the managed Atlas DB above.
- Note on the confusing name: the production Atlas database is literally named `…-test_database`. That string is the PRODUCTION database name — it is NOT the preview DB.

### 2. Which collection does the login path read?
From the **live build source** (`/app/scratch`, extracted from the live run's image source):
- `backend/routers/auth.py` → `POST /auth/login`: `u = await db.users.find_one({"email": body.email})`. The password path is `verify_password(body.password, u["password"])`; on `not u or not verify_password(...)` it returns **HTTP 401 "Invalid credentials"**.
- `backend/deps.py`: `db` is a `_MotorProxy` bound in `init_database()` by `real_db = real_client[os.environ["DB_NAME"]]`. Therefore `db.users` resolves to the collection named **`users`** inside **`os.environ["DB_NAME"]`** — i.e. `users` in `greeting-app-5782-test_database`.
- **No separate auth database, no alternate collection name, no collection prefix** anywhere in the login path. Confirmed.

### 3. Does `users` exist in the production DB, and what's in it?
Against the live run's resolved production DB:
- `list_collections` → 103 collections, and **`users` IS present**.
- `users` count = **1**.
- `users` where `role: admin` count = **1**.
- The single document: `email = admin@nivxray.com`, `role = admin`, `_id = 6a553cdfb94c9e2ac0100544`, `created_at = 2026-07-13T19:30:39Z`. (Password hash field NOT read/returned.)
- So: **PRODUCTION_USERS_COLLECTION_EXISTS = YES**, 1 doc, 1 admin, `admin@nivxray.com` present. No alternative/second admin exists.

### 4. Is the PREVIEW `users` the same storage the live endpoint reads?
**NO.** They are different databases on different clusters:
- Production (live pod): Emergent-managed Atlas, DB `greeting-app-5782-test_database`.
- Preview: the source/agent-env pod's **local `mongod`** (localhost) — a separate database, not reachable from the production pod and not what `POST /api/auth/login` reads in production.
- The `users` collection the owner saw in the preview MongoDB Viewer is therefore a **separate copy** and editing it changes nothing in production.
- **PREVIEW_USERS_IS_LIVE_AUTH = NO.**

### 5. Why is `users` not visible in the production MongoDB Viewer?
Direct evidence **contradicts** the "production has no users collection" hypothesis: `users` IS present in the live production DB and holds the admin. Ruling the candidates:
- ❌ "Production genuinely has no users collection" — FALSE (it exists, 1 doc).
- ❌ "Named differently in production" — FALSE (it is exactly `users`).
- ✅ Most consistent with evidence: the production DB has **103 collections**, and `users` sits deep in an unsorted listing — it was most plausibly **paginated / scrolled past / filtered out of the Viewer listing**, OR the Viewer was pointed at a **different database or the preview side** rather than the production pod's DB. Both are "viewer visibility" problems, not a data problem.
- Consequence for the 401: because the user **does exist**, the production `401 "Invalid credentials"` means the supplied **password did not match the stored bcrypt hash** (wrong-password / stale-hash), NOT "no such user."

### 6. Earlier report cross-check
The earlier census queried `greeting-app-5782-test_database` — which is **the same database the live pod resolves from its own `MONGO_URL`/`DB_NAME`**. The 1-user finding and "no alternative admin accounts" conclusion **re-measured against the live pod's DB today: count=1, admin=1, only `admin@nivxray.com`**. **EARLIER_USER_CENSUS_VALID = YES** — it stands; nothing needs to be withdrawn.
