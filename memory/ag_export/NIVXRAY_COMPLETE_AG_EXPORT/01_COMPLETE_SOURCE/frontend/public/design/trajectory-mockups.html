NivXRay · Device Trajectory · M2 Mockups

Twelve static scenes exploring the redesigned investigation timeline. Every scene renders the same seeded Bumblebee → AdaptixC2 → Akira ransomware case so you can compare states directly. Scenes are hand-drawn SVG — nothing here is React, Konva, or production code. Focus on the investigation methodology — spacing, order, density, ancestry, contrast budget — not the hex values.

Scene 01 · Landing state · Full case

Land First view. The analyst sees a story in 3 seconds. DFS-ancestry order · thin lifelines · red events dominate
Design rationale. The row is now a thin 1-px line, not a pill. Names live in a fixed 180-px left gutter. Ancestry is expressed by indentation glyphs (├─ └─ │) and thin L-connectors that drop from parent lifeline to child lifeline at the exact spawn tick. The only loud colour on the canvas is red — 8 red dots on powershell.exe and locker.exe plus the "RANSOMWARE ACTIVATION · T1486" label pull the eye straight to the moment of compromise. Amber sits at half the visual weight of red. Everything else is monochrome. The canvas is legible without opening the right panel.

Scene 02 · Event hover · tooltip card

Orient Hovering the ransomware event surfaces evidence context. 300 ms delay · verdict pill · MITRE chips · timestamp
Design rationale. Hover a malicious event → tooltip appears after 300 ms with verdict pill, MITRE chips (deterministic, taken from the event, not invented), parent, SHA-256 excerpt. Simultaneously a dashed playhead drops through all rows at the event's timestamp so the analyst sees what else was happening at that instant. Three co-occurring events on other rows get a blue outline — this is how Cisco makes cross-row correlation feel instant.

Scene 03 · Selected event · playhead lock

Attribute Click the event · playhead locks · right panel opens to Evidence.
Design rationale. One click gives the analyst the whole story: playhead locks (solid blue line, not dashed), event gets a 2 px selection ring, right panel jumps to Evidence tab and is fully populated with verdict / command line / SHA / parent / MITRE / detection rule. The Evidence tab structure is the same for every event kind — one predictable place to read.

Scene 04 · Ancestry focus mode

Descend Cmd+click on powershell.exe row: only ancestors + descendants remain visible.
Design rationale. The ancestry focus mode is the workflow analysts want when saying "just show me the chain." Cmd+click any row → only ancestors + descendants remain, everything else collapses. The ancestry L-connectors become solid blue (versus #CBD5E1 when idle) to accentuate the chain. Twelve red dots pop unmistakably.

Scene 05 · Filter drawer · Network only

Widen Slide-out filters · "Network only" collapses rows to ultra-dense view.
Design rationale. Filters live in a slide-out drawer opened via \, not as a permanent row eating vertical real estate. When "Network" is selected, rows that don't match collapse entirely — no empty greyed-out rows. Density is preserved. The two red TOR and IRC destinations pop immediately. That is the "widen" step from the investigation workflow.

Scene 06 · Missing-ancestry empty state

Honest When adapters ship no parent.iid, the canvas says so.
Design rationale. Rather than silently render a broken tree, the canvas tells the truth when adapter data is incomplete. The amber banner is honest: "we don't have parent IIDs, so ancestry connectors are suppressed." Rows still render, still sort by time, still show verdict colour. The banner links to the sort menu so the analyst can pick a fallback order. This is the guardrail against silently misleading the analyst.

Scene 07 · Zoom to compressed sub-second span

Adapt Adaptive axis · relative-seconds mode when case span < 10s.
Design rationale. The current implementation reads "13:04:54 13:04:54 13:04:54" ×12 when the case is sub-second — communicating "time is broken" instead of "time is compressed." The adaptive axis picks its unit from the actual span: T+0.0s for sub-10-second cases, HH:MM:SS for sub-10-minute, HH:MM for sub-day, MMM-DD for anything larger. Deterministic. No guessing.

Scene 08 · Dense enterprise case · 42 rows, 480 events

Stress test The layout has to survive a real SOC-scale case.
Design rationale. The layout must survive a real SOC-scale case. 42 rows fit in 620 px vertical (versus 20 rows in 640 px today). The eye instantly finds two red clusters — powershell subtree, then locker.exe subtree — even in a busy scene. Amber wbadmin/vssadmin events tell the "backup deletion before encryption" story without a caption. This is the density Cisco delivers and we currently don't.

Scene 09 · Landing card · pre-load state

Empty Before data loads, the workspace explains what it is.
Design rationale. The empty state teaches the tool. Instead of blank grey, the landing card explains the product in three lines. No lorem ipsum, no fake data. The moment the analyst picks a case, we transition to Scene 01.

Scene 10 · Sub-canvas: registry drill-down popover

Descend Cmd+click a registry glyph → inline popover expands the touched keys.
Design rationale. A registry event can represent 1–N key mutations. Rather than inflate the canvas with N rows per mutation, we drill down into an inline popover that lists the touched keys in the order they were touched. Each mutation carries its own MITRE technique. This mirrors the "expand" affordance Cisco uses for grouped events without consuming permanent screen space.

Scene 11 · Comparison strip · before / after

Delta Current M1 versus proposed M2. Same data, same viewport.
Design rationale. Same case, same viewport, side-by-side. On the left, 5 rows fit and the pills scream. On the right, 17 rows fit, the red dots on powershell.exe → locker.exe are the only loud thing, and the tree structure is legible without labels. That's the delta we're proposing.

Scene 12 · Header + minimap · full chrome

Chrome One-row header · zoom / fit / filter chips · minimap in the corner.
Design rationale. The chrome collapses to one row · 36 px. Case picker, event counts, filter chips, search, and zoom all live in one strip. The minimap sits in the bottom-right of the canvas (out of the way but always reachable), showing the whole case as a dot field with the current viewport rectangle overlaid. This is the entire non-canvas UI — everything else the user needs is inside the canvas.
