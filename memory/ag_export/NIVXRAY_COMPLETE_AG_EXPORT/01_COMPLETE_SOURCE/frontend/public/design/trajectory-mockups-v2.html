M2 Mockups · v2 · Cisco-corrected

Six scenes rebuilt to match Cisco patterns confirmed from the Secure Endpoint User Guide (pp. 324–366) and the Success Capsule video (2025-03-12). Every rule below is anchored to a verbatim quote in M2_CISCO_CORRECTIONS.md. Only investigation methodology is borrowed — no Cisco branding, colours, or icons are reused.

Scene 01v2 · Landing · two-strip time navigator + yellow compromise bands

Corrected 30-day density with red compromise dots · 24-hour lens · yellow compromise band on the canvas. Axioms 3, 4, 5, 6
Design rationale. Two-strip time nav (axioms 4, 5) sits at the top: 30-day density bars with red compromise dots, then a 24-hour lens with yellow compromise band shading and a draggable viewport window. On the canvas, the yellow compromise band (axiom 3) crosses all rows to mark the 0.48-second compromise window. A dedicated compromise indicator row ("Reflective DLL Injection") sits at the top of the ancestry — clicking it will halo the trigger events (Scene 04v2). Disposition = fill colour: green benign, red malicious (axiom 6). Source events on cmd.exe render as double-circles (parent-of-activity), acted-upon events on files render as single symbols. The powershell.exe row shows five red triangles inside the yellow band — the entire compromise story is legible without opening the right panel.

Scene 02v2 · Hover · tooltip only (no false playhead)

Corrected Playhead removed. Hover reveals evidence card. Nothing else animates.
Design rationale. Cisco doesn't ship a playhead and neither will we. Hover surfaces the tooltip; nothing else animates. This keeps the canvas calm — the hover is a lookup, not a stage-shaking event. Correlation across rows now belongs entirely to the compromise row + blue halo pattern (Scene 04v2), which is a stronger signal than "same-timestamp events."

Scene 03v2 · Selection · Event Details pane (verbatim Cisco naming)

Corrected Right pane populates on click. Same layout for every event kind.
Design rationale. The right pane's field list is now verbatim from the Cisco User Guide pp. 325–342: File Name, File Path, Execution Context, Command Line, SHA-256, Parent Process, Detection, engine, Quarantine action. The MITRE and History tabs are secondary. Q-Audit means the quarantine action was audit-mode only (as Cisco describes for Command Line Capture policies) — no automatic action was taken. The "Add SHA to allow/block list" pair at the bottom is the Cisco-standard remediation shortcut.

Scene 04v2 · Compromise row · blue halo on trigger events

Corrected Click the compromise row · Cisco's "blue halo" lights the events that triggered it. Axiom 7
Design rationale. The Cisco pattern is unambiguous: "Clicking on the compromise event will also highlight the individual events that triggered it with a blue halo." The compromise row is the entry point; clicking it turns non-trigger events on other rows to 50% opacity and adds a 1.6-px blue halo to trigger events. Eleven halos on three rows immediately explain "why did this indicator fire?" without a single word of copy.

Scene 05v2 · Filter drawer · five required categories

Corrected Activity · System · Disposition · Flags · File Type — all five required (Cisco rule).
Design rationale. The five categories are non-negotiable per the Cisco User Guide (p. 337): "At least one item from each category must be selected." The drawer surfaces all five and shades the active state. On the right, the canvas has already collapsed to the 3 surviving rows and 8 surviving events. This is what "network only" or "malicious only" should feel like — surgical, not merely dimmed.

Scene 06v2 · Glyph legend · source vs acted-upon

New Cisco's double-circle / single-circle distinction · every glyph explained.
only allowed for compromise-window shading and system flag chips. Blue (#2563EB) is only allowed for compromise blue halos, selection rings, and links. Everything else on the canvas is a shade of gray from #0F172A to #E2E8F0.

Any pull request that adds a new colour to the canvas must justify itself against this legend.
