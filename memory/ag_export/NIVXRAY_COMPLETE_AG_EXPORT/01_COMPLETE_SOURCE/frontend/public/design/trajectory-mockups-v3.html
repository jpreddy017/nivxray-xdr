Scene 07v3 · Dense enterprise case · yellow band is a TIME COLUMN

Stress test 42 rows · 480 events · one vertical yellow window marks the compromise hour. No pills. No per-row shading. Amber is a time overlay only.
Design rationale. Same scene as v1 Scene 08, now correct. The yellow band is a vertical column at the compromise hour, not per-row pills. All 42 rows keep clean thin lifelines. Red events fall inside the yellow window. Amber never touches an entity. The eye finds the compromise in under a second — that's the Cisco pattern working.

Scene 08v3 · Empty state · before a case is picked

Empty The empty state teaches what Device Trajectory is.
Design rationale. Before a case is picked the workspace teaches its own purpose in three lines. The sidebar lists cases with their case-level headline (events · compromises) so an analyst can triage what to open next. One primary CTA — "Open latest case" — for the common path.

Scene 09v3 · Loading state · rows and events stream in

Loading Skeleton lifelines · shimmer glyphs · counters tick as data arrives.
Design rationale. Progressive loading — not a spinner. Skeleton bars show row outlines the moment we know row keys; events pop in as their timestamps arrive. The counter 42 / 500 and the fetch line at the bottom make progress observable. The analyst can click already-loaded events without waiting for the last batch.

Scene 10v3 · Error state · adapter fails or backend times out

Error Honest failure · surface the fault · offer a retry.
Design rationale. When the backend fails, the workspace refuses to lie. The banner surfaces the HTTP status, the upstream module, the correlation-id, and the exact timestamp of the failure. Three actions: Retry (primary), Copy correlation-id (for filing an incident), Open logs (for the DFIR engineer). Auto-retry is on but visible, not silent.

Scene 11v3 · Keyboard cheatsheet · press ?

Traversal Every keystroke an analyst needs, on one card.
Design rationale. Every high-frequency SOC action has a shortcut, and the shortcut card is one keystroke (?) away. Three columns match the mental model: Navigation (where am I?) · Selection (what am I looking at?) · Filters & Views (what should I hide?). Keyboard is a first-class citizen — Cisco relies heavily on it and so should we.

Scene 12v3 · Extreme zoom · 2-second interval column

Zoom One column = 2 seconds · every event has room to breathe.
Design rationale. At the deepest zoom (2-second columns per Cisco spec) each event gets an inline caption — the extra horizontal room is spent on readable evidence fragments (-enc <stage2>, comsvcs.dll,MiniDump). This is where the analyst reconstructs the technical detail of the compromise. Zooming back out collapses the captions.

Scene 13v3 · Dark theme · same rules, inverted palette

Preference Optional dark mode for night-shift SOC analysts. Same contrast budget.
Design rationale. Dark mode is not a re-design; it is the same design with an inverted palette. Green shifts to #22C55E, red to #F87171, background to #0B1220, panel to #111827. Contrast ratios remain identical. Amber and blue keep the same hex — they read on both backgrounds. Analysts on night shift get a low-glare workspace with zero behavior changes.

Scene 14v3 · Multi-case comparison · shared time axis

Advanced Two cases stacked · shared time axis · same-endpoint attack recurrence.
Design rationale. When investigators discover a repeat compromise on the same asset, the comparison view stacks two cases on one time axis. The visual alignment reveals that both campaigns hit powershell then encryption at almost identical time offsets — a pattern that would take days to spot in separate cases. Case chips (left-edge colour) make each case's disposition immediately identifiable.
