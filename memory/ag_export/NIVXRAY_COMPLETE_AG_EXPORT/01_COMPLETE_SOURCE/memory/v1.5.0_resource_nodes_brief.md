# v1.5.0 · Behaviour Graph enhancement — First-class Resource Nodes

**Recorded:** 2026-07-28 (SME review of v1.4.2 Investigation Graph)
**Severity:** P1 · behaviour-graph modeling gap
**Schema impact:** MINOR bump `1.1.0 → 1.2.0`

---

## Problem — WinRM disappears from the graph

The Behaviour Graph currently emits **behaviour-category nodes**
(`lateral_movement`, `defense_evasion`, ...) with the affected
resource only referenced inside `Evidence.observation` strings.

For the T15 PsExec + WinRM + firewall sample the analyst gets:

```
[lateral_movement]  ─ configures →  ???
[defense_evasion]   ─ modifies   →  ???
```

They cannot see **which service was configured** or **which
firewall rule groups were enabled** without reading every
Evidence rationale.

## SME target (verbatim recommendation)

```
PowerShell.exe
    │
    ├── Enable-PSRemoting → WinRM Service
    ├── Set-Service WinRM → Startup = Automatic
    ├── Start-Service     → WinRM Running
    └── Enable-NetFirewallRule → Windows Remote Management
                              → File and Printer Sharing
```

## Design

1. **New node kinds in `BehaviorKind`** (schema `1.2.0`):
   - `service`         — Windows / Linux service (e.g. `WinRM`)
   - `firewall_rule`   — a firewall rule / display-group name
   - `feature`         — an OS feature or capability (e.g. `PSRemoting`)
   - `scheduled_task`  — future use
   *(`file` and `registry` remain arg-kinds — they are already
    first-class via `BehaviorArgKind`.)*

2. **New edge kinds in `BehaviorEdgeKind`**:
   - `configures`  — behaviour ⇒ resource
   - `starts`      — behaviour ⇒ service
   - `enables`     — behaviour ⇒ feature / firewall rule
   - `modifies`    — behaviour ⇒ any resource

3. **Intent rules emit resource nodes alongside behaviour nodes**.
   Every resource node cites the same Evidence as its behaviour
   parent — determinism preserved.

4. **Schema doc + CI freeze test** updated in the same commit.
   Version bumps to `1.2.0`. `_EXPECTED_KIND_NAMES` and
   `_EXPECTED_EDGE_NAMES` in `test_behavior_graph_schema_freeze.py`
   updated in lockstep.

5. **Analyst Report** exposes `behavior_graph` unchanged (it's
   already serialised). The Frontend graph visualisation renders
   resource nodes with a different tone so analysts can
   distinguish process/behaviour nodes from resource nodes.

## Acceptance criteria

1. T15 sample produces a graph containing `WinRM`, `PSRemoting`,
   `Windows Remote Management`, and `File and Printer Sharing`
   as **first-class nodes**.
2. Typed edges (`configures` / `starts` / `enables` / `modifies`)
   are populated correctly.
3. Every resource node cites Evidence — nothing invented.
4. Schema doc reflects `1.2.0` with the new kinds and edges.
5. Freeze test locks the new schema.
6. All 331 existing tests remain green; new resource-node tests
   added; T15 corpus expects the new nodes.
7. Determinism preserved — replay produces byte-identical graph.

## Non-goals for this ticket

- No changes to intent rules that aren't emitting resources.
- No PDF export, no correlation, no static control flow.
- No changes to the Verdict Engine composition rules.
