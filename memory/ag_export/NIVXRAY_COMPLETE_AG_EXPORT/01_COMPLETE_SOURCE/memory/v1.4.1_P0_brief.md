    Enable-PSRemoting -Force -SkipNetworkProfileCheck

    Enable-NetFirewallRule -DisplayGroup 'File and Printer Sharing'

## Observed defect (both outputs are wrong)

| Panel | Output | Problem |
| ----- | ------ | ------- |
| Investigation Brain | `BENIGN · 60` · "No adversarial intent" | Under-inferred. Ignores observed behaviour. |
| Legacy Analyst Summary | `CRITICAL · 95%` · "textbook lateral movement + persistence commonly seen in ransomware pre-deployment phases and APT infrastructure setup" | Over-inferred. Invents attribution without evidence. |

**Neither is the desired deterministic output.**

## Correct output shape

```
Verdict:    HIGH-RISK ADMINISTRATIVE ACTIVITY
Confidence: 85–90

Observed Evidence (high confidence — directly supported by the payload)
  · PsExec remote execution
  · Explicit credentials passed on the command line
  · Elevated execution (`-h`)
  · Remote PowerShell invocation
  · Enable PSRemoting
  · Configure WinRM startup (Automatic)
  · Start WinRM service
  · Enable firewall rules for WinRM and File/Print sharing
  · Establishes remote administration capability

Behavioral Assessment (derived from Behavior Graph)
  · credentialed_remote_execution → remote_management_enablement
  · Behavior chain is consistent with authorised administration
    OR post-compromise lateral movement — cannot be distinguished
    from the artefact alone.

Inferences (clearly labelled hypotheses — NEVER presented as facts)
  · May facilitate later lateral movement
  · May support later persistence
  · May be consistent with post-compromise activity

Unknowns (honesty)
  · Whether the execution was authorised
  · Whether `mativadmin` is an approved administrator
  · Whether additional payloads executed on 10.253.34.27 afterwards
  · No corroborating evidence for ransomware / APT — do not attribute
```

## Three root causes to fix

### RC-1 · Verdict Engine reasons over isolated indicators, not composition
**Current** — `no downloader ∧ no known-family ∧ no registry-Run → BENIGN`.
**Required** — score the Behavior Graph **composition**:
`credentialed_remote_execution + remote_management_enablement + firewall_configuration → HIGH-RISK`.

The Verdict Engine must consume the canonical `BehaviorGraph`, not
re-derive verdict from raw intent hits.

### RC-2 · Behavior Graph taxonomy has real gaps
Sample proves the following canonical nodes are missing:

- `credentialed_remote_execution`   (PsExec / WMI / WinRM with explicit `-u -p`)
- `remote_management_enablement`    (`Enable-PSRemoting`, `Set-Service WinRM Automatic`)
- `winrm_configuration`             (WinRM listeners, TrustedHosts, StartupType)
- `firewall_configuration`          (`Enable-NetFirewallRule`, `netsh advfirewall`)
- `elevated_remote_execution`       (`-h` / SYSTEM integrity remote)
- `remote_administration_capability` (composite — the *combined* observable)

Adding these is a **Behavior Graph schema MINOR bump `1.0.0 → 1.1.0`**,
which is exactly what the schema-freeze contract in
`BEHAVIOR_GRAPH_SCHEMA.md` was built to control. Update:

- `behavior/models.py::BehaviorKind` enum
- `BEHAVIOR_GRAPH_SCHEMA.md` node-kinds table
- `BEHAVIOR_GRAPH_SCHEMA_VERSION = "1.1.0"`
- `tests/test_behavior_graph_schema_freeze.py` `_EXPECTED_KIND_NAMES`
  + `_EXPECTED_SCHEMA_VERSION`

New Intent rules to emit these behaviours (deterministic, evidence-only):

- `psexec_credentialed`      → `credentialed_remote_execution` + `elevated_remote_execution` if `-h/-s`
- `winrm_configuration`      → `remote_management_enablement` + `winrm_configuration`
- `firewall_configuration`   → `firewall_configuration`

### RC-3 · Analyst Summary invents conclusions
The current legacy Analyst Summary is **judging** ("textbook
ransomware pre-deployment", "APT infrastructure setup"). It must
become a pure **translator** of the canonical `InvestigationResult`.

Rule: the Analyst Summary generator has read-only access to:

- `result.behavior` (nodes + edges)
- `result.report.iocs`
- `result.report.mitre`
- `result.verdict.band` + `confidence` + `reason`

It **may not** independently classify the artefact, attribute a
malware family, or invent a campaign. It must produce output in
four labelled sections: **Observed Evidence · Behavioral
Assessment · Inferences · Unknowns.**

Where the sample is ambiguous ("consistent with authorised
administration OR post-compromise lateral movement"), the summary
MUST say so and put the ambiguity in Unknowns — never resolve it
by guessing.

## Acceptance criteria

1. Investigation Brain returns `HIGH-RISK ADMINISTRATIVE ACTIVITY · 85-90` (or equivalent named band) for the test case above — **not** `BENIGN`.
2. Analyst Summary no longer references *ransomware*, *APT*, *campaign*, *textbook*, or any word not supported by evidence.
3. Every UI panel on the Workspace renders from **one** canonical `investigation` object — no independent verdict computation anywhere in the frontend.
4. Behavior Graph schema bumped to `1.1.0`; CI freeze test passes with the new taxonomy locked.
5. New Trust-Corpus sample **T15 · psexec_winrm_lateral_admin** added with declared expected verdict, behaviour kinds, MITRE, IOCs. Regression MUST fail before RC-1/RC-2/RC-3 fixes and MUST pass after.
6. All existing 331 tests remain green.
7. Determinism preserved — replay of the same sample yields byte-identical `BehaviorGraph` and `verdict`.

1. **T15 Trust Corpus sample first** — declared ground truth for the sample. Regression fails immediately → gives us a red bar to drive against.

6. **Trust Corpus 15/15 green** + full 332/332 regression + production smoke on the LIVE URL for the T15 sample.
