## 5. On the 0 reasoning_steps (per owner architectural note)

The owner's directive was explicit:

> *"do not let the 0 reasoning steps become a reason to add MITRE logic to Phase 3. If the correct Sample.docx produces MITRE-relevant evidence, the Executor should expose that evidence into the authoritative SSOT. MITRE presentation/matrix/Attack Story/recommendations remain Phase 4 projections, as designed."*

Applied strictly. Analysis:

- The real Sample.docx is a **ZIP archive**. Its raw bytes contain the ZIP central directory + XML fragments as compressed binary. The MITRE_MAP capability today runs a needle-scan against the raw text projection, which for a ZIP is largely binary noise. Hence 0 matches — architecturally expected.
- Sample.docx's MITRE-relevant evidence lives inside `word/document.xml` (the unpacked XML). Exposing it requires a **text-extraction** step after `ARCHIVE_EXTRACT` that reads the extracted `word/document.xml` and hands it to `MITRE_MAP` and `IOC_EXTRACTOR`.
- That extraction is a **capability extension** (a new/enhanced Analyzer plug-in), NOT a projection. It could land in a Phase 3.x follow-up OR as part of Phase 5's EntryAdapter work when the docx-reinvestigate route wires bytes through the canonical lifecycle.
- **No Phase 3 code was changed to add MITRE logic during this verification.** The `MITRE_MAP` plug-in remains exactly as it was implemented in Phase 3. The 0 reasoning_steps result is a faithful reflection of the current capability set, not a bug in the executor architecture.
