### 0.1 · Stage Isolation Rule

Each acquisition stage exposes exactly ONE public function and
lives in its own module:

```
services/veee/stage_1_html.py           acquire_html()
services/veee/stage_2_images.py         discover_images()
services/veee/image_classifier.py       classify_image()
services/veee/ocr_engine.py             extract_text()   → OCRResult
services/veee/line_joiner.py            join_lines()
services/veee/evidence_extractor.py     normalize()
services/veee/provenance_schema.py      validate()
services/veee/append.py                 append_evidence()
```

Hard rules:

* **No stage may directly call a later stage.**  Data flows only
  through the orchestrator (`services/veee/__init__.py`).
* **No stage may reach across to a sibling.**  If stage N needs
  data stage M produced, stage M returns it explicitly and the
  orchestrator hands it to N.
* Every stage MUST be independently unit-testable with a
  synthetic input — no HTTP calls, no filesystem side effects
  outside the tempdir contract already established.

### 0.2 · Never-Modify-Evidence Rule

VEEE MUST NEVER mutate an existing entry in
``structured_blocks``.  Only append.

```
BEFORE VEEE                        AFTER VEEE
────────────                       ──────────
HTML  #1                           HTML  #1     ← unchanged
HTML  #2                           HTML  #2     ← unchanged
HTML  #3                           HTML  #3     ← unchanged
                                   IMAGE #1     ← appended
                                   IMAGE #2     ← appended
                                   IMAGE #3     ← appended
```

* HTML evidence is never overwritten by OCR evidence.
* HTML evidence is never removed even if VEEE recovers the same
  text from an image.
* If a duplicate is detected (OCR text matches an existing HTML
  paragraph), the OCR record is still appended with its own
  provenance — deduplication is a downstream concern, not
  acquisition's.

This preserves reproducibility and makes the "additivity"
release-gate invariant (§3.2) trivially verifiable.

## 3 · Release Gate Invariants  (all four MUST pass)

### 3.1 · Flag-OFF byte-identity
```python
assert acquire(url, flag=False) == baseline_snapshot(url)
```

### 3.2 · Additivity — VEEE never reduces evidence
```python
off = acquire(url, flag=False)
on  = acquire(url, flag=True)
assert len(on.structured_blocks) >= len(off.structured_blocks)
# Furthermore, every block in off must be present in on.
assert set(off.blocks) <= set(on.blocks)
```

```
ocr_confidence    = float in [0.0, 1.0]
```

### 3.5 · Deterministic Acquisition
Given the same article, configuration, and OCR engine version,
VEEE MUST produce byte-identical ``NormalizedEvidence`` records
across repeated runs.

Deterministic contract:
* Identical evidence count.
* Identical ``text`` per record.
* Identical ``provenance`` (including bounding boxes, confidence
  values, SHA256).
* Identical record ORDERING (or a deterministic sort key — see
  below).
* No timestamps, UUIDs, monotonic IDs, or wall-clock values
  inside emitted evidence.  Freshness is tracked *outside* the
  record on ``structured_blocks[].meta.acquired_at`` — not on the
  ``NormalizedEvidence`` payload itself.

Sort key for deterministic ordering:

```
(image_url, bounding_box.y, bounding_box.x, image_sha256)
```

A regression test (`tests/test_veee_determinism.py`) MUST run
the full Vendor Corpus v1 twice and assert the resulting
``NormalizedEvidence[]`` arrays are equal (``==``).  Any failure
is a hard-fail CI event — the deterministic-acquisition guarantee
underpins every downstream regression test.

## 3.6 · Acquisition Pipeline · Explicit Stage Contract

Every stage has a single responsibility and a well-defined
input / output contract.  Skipping, merging, or reordering
stages is a P0.15C violation.

```
URL
 │
 ▼
HTML Acquisition          → HTML text  · <img> URLs · structured HTML blocks
 │
 ▼
Image Discovery            → List[(image_url, page, alt, context)]
 │
 ▼
Image Classification       → decides is_code_screenshot per image
 │
 ▼
OCR                        → OCRResult{lines[], bboxes, confidence}
 │
 ▼
OCR Line Joining           → OCRResult with merged multi-line commands
 │
 ▼
Evidence Normalization     → NormalizedEvidence[]
 │
 ▼
Provenance Validation      → schema-checked NormalizedEvidence[]
                              (fails-safe to "skipped" on missing fields)
 │
 ▼
Append to structured_blocks
```

Each stage lives in its own module inside ``services/veee/``:

| Stage | Module | Emits |
|-------|--------|-------|
| HTML Acquisition       | *(existing IDA-3 adapter)*          | HTML + img refs |
| Image Discovery        | `services/veee/image_discovery.py`  | `List[ImageRef]` |
| Image Classification   | `services/veee/image_classifier.py` | `{is_code_screenshot, reason, …}` |
| OCR                    | `services/veee/ocr_engine.py`       | `OCRResult` |
| OCR Line Joining       | `services/veee/line_joiner.py`      | `OCRResult` (merged) |
| Evidence Normalization | `services/veee/evidence_extractor.py` | `NormalizedEvidence[]` |
| Provenance Validation  | `services/veee/provenance_schema.py` | validated records or `skipped` |

## 4 · Mandatory OCR Provenance Schema

```jsonc
{
  "type":       "commandline" | "caption" | "ioc",
  "text":       "<recovered text>",
  "provenance": {
      "source":            "image",        // required
      "acquisition_level": "P3",           // required
      "image_url":         "https://…",    // required if fetched from URL
      "image_sha256":      "<hex>",        // required
      "bounding_box":      { "x": int, "y": int,
                             "w": int, "h": int }, // required
      "ocr_engine":        "tesseract-5",   // required
      "ocr_confidence":    0.0..1.0,        // required
      "veee_version":      "1.0",           // required
      "joined_from_lines": [1, 2, 3]        // required IF line-joining ran
  }
}
```

A schema validator (`services/veee/provenance_schema.py`) MUST
run inside VEEE before any record is emitted; on any missing
field the record is downgraded to a `skipped` provenance
breadcrumb with `reason="provenance_incomplete"`.
