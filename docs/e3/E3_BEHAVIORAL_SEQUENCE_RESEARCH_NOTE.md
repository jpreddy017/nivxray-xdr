# E3 Behavioral + Sequence Engine: Bounded Research Note

- **Scope:** public, legitimate documentation only.
- **What was copied:** nothing. No vendor code, rules, UI assets, private APIs or undocumented internals were used.
- **Cisco Secure Endpoint** is used as a *functional reference model*. NivXForge's design below is independent.

## Concept matrix (independent NivXForge design)

| Capability | Problem | Telemetry | Entities / state | Correlation | Local vs central | Generation | Historical | Evidence | FP control | Provenance | Authorization | Scale |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| Behavioral sequence detection | Single events are benign; chains are malicious | process start / parent, command line, file create, registry set, DNS, network, logon, prior detections | tenant, endpoint, process_iid (M1), parent GUID/PID, user, file path/hash, domain/IP | ordered stages; same_process / parent_child / same_user / same_value / dns_to_ip | Central (sensors have no local engine today) | deterministic matcher over a bounded window | replay via the same path | evidence_refs with raw_id + canonical_event_id | rule exclusions, tenant suppression, adjustments, thresholds | rule content hash + version, normalizer, identity authority, mode/trigger | none (detections only; response is E1) | per-(tenant, endpoint) bounded windows, budgets |
