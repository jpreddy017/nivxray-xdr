## 1. Executive Summary & Staging Philosophy

The Native Dynamic Sandbox is architected as an **evidence-producing subsystem**. It executes untrusted artifacts inside isolated hypervisor guests and emits canonical behavioral, network, and file evidence directly to the NivXRay XDR evidence pipeline.

**Crucial Architecture Contract**:
- The Sandbox does **NOT** create a shadow reasoning engine, IKG, or verdict engine.
- All evidence generated by detonation flows straight into NivXRay's canonical evidence pipeline (`workspace_cases.verdict_stage2.evidence[]`).
- The current implementation state of the dynamic execution engine is **DESIGN ONLY / CAPABILITY UNAVAILABLE**.
- The static analysis and artifact decoding engines are **FULLY OPERATIONAL LIVE NOW** (`/app/backend/services/artifact_intelligence/analyzers/` PE, ELF, Office, PDF, Archive, Shellcode analyzers + 59 decoders).

## 3. Surface Staging & UI Representation

### 3.1 Surface 1: Detonation Intake & Profiling (`/sandbox/submit`)
- **Staging Tier**: `HYBRID` (Static Router = `LIVE NOW`, Dynamic Execution Config = `DESIGN ONLY`).
- **UI Contract**:
  - File / URL dropzone accepts PE, ELF, Office, PDF, Script, or Archive binaries.
  - Submitting triggers the operational **Static Analysis Pipeline** immediately, extracting PE headers, entropy, sections, hashes (MD5, SHA1, SHA256, SSDEEP, Imphash), and running YARA signatures.
  - Hypervisor selection controls (Windows 11 x64, Ubuntu 22.04 eBPF, Airgap / INETSim) are rendered with a clear operational badge:  
    `⊘ DYNAMIC DETONATION ENGINE UNAVAILABLE · STATIC ANALYSIS COMPLETED`.

### 3.2 Surface 2: Live Hypervisor Console & Syscall Stream (`/sandbox/live/:jobId`)
- **Staging Tier**: `DESIGN ONLY`.
- **UI Contract**:
  - Renders a high-fidelity dark console frame with simulated screen dimensions.
  - Center Canvas displays an explicit, un-faked overlay banner:  
    `⊘ HYPERVISOR DETONATION ENGINE NOT IMPLEMENTED · DESIGN-ONLY PROTOTYPE`.
  - Kernel Syscall Stream displays live static decoder events when available or remains cleanly paused without emitting synthetic syscalls.

### 3.3 Surface 3: Dynamic Detonation Analysis Report (`/sandbox/reports/:jobId`)
- **Staging Tier**: `HYBRID`.
- **6 Dissection Tabs**:
  1. **Static Analysis & Hashes**: `LIVE NOW` — Backed by real PE/ELF/Office/PDF analyzers and 59 decoders.
  2. **Behavioral Process Graph**: `DESIGN ONLY` — Renders `⊘ CAPABILITY UNAVAILABLE` badge until VM execution driver is connected.
  3. **Network Activity & Sockets**: `DESIGN ONLY` — Renders `⊘ CAPABILITY UNAVAILABLE` badge.
  4. **File System Modifications**: `HYBRID` — Displays embedded artifacts extracted by decoders (`LIVE NOW`); dynamic drops (`DESIGN ONLY`).
  5. **Windows Registry**: `DESIGN ONLY` — Renders `⊘ CAPABILITY UNAVAILABLE` badge.
  6. **Extracted Config & C2**: `LIVE NOW` — Displays C2 IP/domain extraction backed by operational decoders.

### 3.4 Surface 4: Closed-Loop Convergence Bridge (`/sandbox/bridge/:jobId`)
- **Staging Tier**: `LIVE NOW` (for static IOCs & Decoded Payloads).
- **UI Contract**:
  - Allows analysts to push extracted hashes and C2 domains directly to the Rule Studio (`/xdr/rule-studio`) or submit extracted payloads to the 59-Decoder Feedback Loop (`/api/decode-feedback`).

## 4. Non-Misleading UX Presentation Principles

1. **Clear Banner Demarcation**:
   Every Sandbox UI surface displays the persistent header banner:
   `⚠️ REPRESENTATIVE / PROTOTYPE DATA — Operational UI/UX Contract for Sandbox Implementation`.
2. **No Mock Telemetry**:
   Dynamic tabs MUST NOT display simulated or synthetic PIDs, process names, or IP connections as if they were real execution traces.
3. **Credible Static Foundation**:
   Surfacing the 6 real static analyzers and 59 decoders provides analysts with immediate, authentic utility while keeping the dynamic sandbox bounds honest.
