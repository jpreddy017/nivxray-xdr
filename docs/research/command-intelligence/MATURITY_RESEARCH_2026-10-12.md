# Targeted static deobfuscation research and decisions

Research was limited to selecting bounded additions to the existing engine, not importing another decoder. No upstream production code or third-party dependency was added.

| Technology / primary source | License inspected | Technique and compatibility decision |
| --- | --- | --- |
| [CyberChef Magic source](https://github.com/gchq/CyberChef/blob/master/src/core/lib/Magic.mjs), existing npm 11.5.0 source checkout | Apache-2.0 | Pattern/entropy gates, recursive speculative transformations, cycle pruning, recipe retention and statistical ranking. Keep NivXRay's existing bounded queue/hash recipes. Improve scope-aware ranking; statistics must not authorize canonical promotion. Full npm export has known dependency-loading issues; existing six-codec research harness is explicitly restricted. |
| [MinusOne](https://github.com/airbus-cert/minusone) | MIT | Tree-sitter plus static node inference/forward propagation is the closest fit. Reuse NivXRay's existing tokenizer and implement a small typed constant AST, avoiding Rust/native grammar packaging in this fast track. No source copied. Existing executed pyminusone 0.4.1 comparison remains useful but is not proof of full parity. |
| [PowerPeeler](https://github.com/zhengbili/PowerPeeler), [paper](https://arxiv.org/abs/2406.04027) | GPL-2.0 | Instruction/AST-linked dynamic recovery requires running scripts in a modified PowerShell environment. Valuable future isolated-lab research, incompatible with normal static-only application execution policy; no integration or copied code. |
| [PowerDecode](https://github.com/Malandrone/PowerDecode) | GPL-3.0 | Multilayer PS recovery and behavioral observations, including dynamic analysis/network checks. Do not import/run it in the API. Recognize safe syntax and deterministic constants independently; no network checks or copied code. |
| [PowerShell ParseInput](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.language.parser.parseinput), [operator semantics](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_operators) | Documentation consulted, not code imported | Native parsing is distinct from executing a script, but hosting .NET/PowerShell would add runtime packaging and isolation work. Reuse local tokenizer now; refuse culture-sensitive formatting, coercion, scoped variables, interpolation and side-effecting calls. Native grammar validation remains a future acceptance improvement. |
| [CMD documentation](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd) | Documentation consulted | Explicit `/v:on` enables delayed expansion. Support one exact SET→ECHO literal template; do not infer percent expansion from a SET earlier on a compound line. Preserve carets before metacharacters, unsupported flags and surrounding evidence. |
| [FLOSS](https://github.com/mandiant/flare-floss) | Apache-2.0 | Binary string reconstruction is relevant conceptually to pure XOR/arithmetic maps. Binary emulation, disassembly and binary-loader dependencies do not fit this command-line fast track. Implement typed finite maps only; arbitrary decoder loops remain unresolved. |
| [capa](https://github.com/mandiant/capa) | Apache-2.0 | Correlating multiple capability features is useful for injection-related evidence. Executable/sandbox-report loaders are outside scope. Add small explicit command syntax rules with supporting spans; no capa rules copied and no maliciousness/ATT&CK promotion. |

Performance/security decision: no external parser process, no shell/pwsh invocation, no eval/exec and no URL fetching. Constant parsing caps input/tokens/nodes/depth/items/operations and checks string expansion before joining. Existing automatic traversal, CI-09 codecs, worker admission/timeouts and cleanup remain authoritative.

Audit found existing `powershell_ast.py`, RC5 parser/interpreter/SIR, V2 `ps_ast` and semantic mini/inline XOR plugins. Some broader legacy materializers use permissive coercion or render unresolved values; they are not automatically trusted for canonical evidence. The new restricted pass reuses V2 tokenization but verifies token coverage (the existing tokenizer may skip unrecognized characters), closed strings, supported statement grammar and exact typed operations. No legacy evaluator or result contract is replaced.

Reference comparison: `MATURITY_REFERENCE_COMPARISON.jsonl` reruns the recorded six MinusOne and six restricted Magic fixtures against this candidate, not the tools' entire operation sets. Existing reference outputs and versions are retained. NivXRay still refuses the MinusOne double-quoted variable-interpolation example; broader interpolation and native grammar support are explicit limitations. Unsupported upstream tools were not run on submitted samples.
