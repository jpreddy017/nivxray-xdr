# CI-09 legacy decoder resource hardening

Baseline: `c3dc3c4eea11d3f4b13770721922bb692f8c9c42`, draft PR #11.
Scope: the existing shared decoder and its callers; no replacement decoder.
Release recommendation: **NO-GO**. **CI-09 is CLOSED within the reviewed scope**; staging and owner gates remain.

## Root cause and changes

Legacy endpoints used a thread timeout that returned while decoding continued. Codec detection and recovery called native unbounded decompressors, so automatic-mode limits did not protect legacy mode. Different consumers also called shared analysis functions directly, outside route-level limits.

One shared legacy entry decorator now enforces input limits, spawns a killable worker, and reuses a cumulative budget for nested calls. Async routes offload supervision without blocking the event loop. Server-owned module/function references select the work; submitted strings never select a callable or execute as scripts. Recipe replay moved to an importable function and retains its success/error response shape. Worker bootstrap registers the same extended operations as the server.

Local codec facades replace decompression calls during both detection and decoding: gzip, zlib/raw deflate, bzip2, LZMA, Brotli, Snappy, LZ4 frame/block and Zstandard. They use bounded streaming APIs or validate allocation sizes before native decoding. Stdlib modules are not globally monkeypatched. Resource refusals bypass legacy broad exception fallbacks and become explicit HTTP 413/503/504 responses at the outer boundary; no refused result becomes canonical evidence.

## Resource profile

- Command input: 16 KiB UTF-8/bytes. Archive API has a fixed server-owned 128 KiB binary-input profile; clients cannot enlarge it.
- Each retained string/bytes artifact or decompression output: 128 KiB. Aggregate retained/generated bytes: 1 MiB, conservatively charged across nested operations and separate workers within the request. Result traversal caps 10,000 objects; serialized report cap 8 MiB.
- Expansion ratio: 128x, minimum 1 KiB allowance. LZMA dictionary and Zstandard window: 64 MiB maximum.
- Legacy nesting: 32; total entry steps: 256. Magic: depth 12, branches 8, returned top 20. Recipes: 32 steps. Recursive peeler/archive: depth 12. Workspace retains its existing depth 16 ceiling.
- Archive metadata: at most 1,024 members; declared aggregate 1 MiB, individual member 128 KiB, bounded reads and ratio checks. Recursive output retains a maximum of 256 children. Optional archive libraries/tools still require deployment-specific validation.
- Two active decoder workers per API process, shared by automatic and legacy modes; overflow returns 503 without adding a decoder work queue.
- Legacy wall deadline: 25 seconds maximum including child startup; Linux RLIMIT_AS 1 GiB and CPU 25/26 seconds. Automatic mode retains its existing four-second worker deadline.
- Parent reads the private bounded result file only after worker exit. Timeout terminates/reaps the worker before return. Worker-owned process groups are cleaned on success, failure and timeout, including utility descendants. Admission is released after cleanup.
- HTTP budgets exclude ASGI lifespan so startup tasks cannot inherit an expiring request budget. Authentication and tenant resolution remain in the parent application.

These are application limits, not an OS security sandbox or a host-wide resource quota. Capacity multiplies by API-process count; cgroup/host sizing, total RSS and deployment worker settings remain staging gates. No submitted script is executed. The deliberate test utility is server-authored harmless sleep/marker code.
