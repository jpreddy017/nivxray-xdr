fix(edr_trajectory): versioned context-free identity encoding with legacy aliases

Follow-up on 2c64e0c, which is PRESERVED as the parent. Repairs the two export
defects reproduced by independent review on that exact source.

DEFECTS REPRODUCED (synthetic, tenant t; A=(0,"same") B=(1,"same") C=(2,"r0:same"))
  before:  A       -> 1 row,  1 unique id,  ids=['same']
           A+B     -> 2 rows, 2 unique ids, ids=['r0:same','r1:same']
           A+B+C   -> 3 rows, only 2 UNIQUE IDS, suppressed=0
  (1) the exported id changed with page/filter composition, so a cursor or deep
      link was only valid for the composition that minted it;
  (2) conditional qualification could collide with a legitimate RAW identity
      whose value was literally prefix-shaped.

CONTRACT CHOICE
  event_id = "e3i1:<rank>:<base64url_nopad(value)>", applied UNCONDITIONALLY.
    - versioned: `e3i1` is explicit, and decode_identity() rejects other
      versions instead of guessing.
    - context-free: a pure function of (rank, value), so subset and superset
      pages export the same id. Verified invariant across A, A+B, A+B+C, C+B+A.
    - unforgeable: base64url cannot contain ':', so "<ver>:<rank>:<payload>" is
      unambiguous and no raw value can impersonate an encoded one. A raw
      "r0:same" at rank 2 now exports e3i1:2:cjA6c2FtZQ, distinct from
      e3i1:0:c2FtZQ.
  after:   A+B+C   -> 3 rows, 3 unique ids, suppressed=0

SELECTION WHEN A HIGHER-RANKED KEY ARRIVES LATER
  Qualification alone cannot fix this, as the review noted: a later page can
  bridge in a higher-ranked identity and change which identity leads. So every
  identity the group holds is published:
    identity_aliases   encoded ids for ALL of the group's keys
    legacy_event_ids   the bare values older builds exported
  An id minted before the rank rose still resolves, instead of 404-ing.

NEVER SELECTS AMONG AMBIGUOUS ALIASES
  identity.resolve_identity() is tenant-scoped; exact/encoded ids resolve
  directly, and a legacy bare id matching more than one row raises
  AmbiguousIdentity rather than choosing.
  production_adapter.resolve_evidence() mirrors this on the real walk: exact and
  alias hits resolve on sight, legacy hits are ACCUMULATED across the walk, and
  a multi-match returns state FOCUS_AMBIGUOUS with the candidate list and
  event=None. A single legacy hit resolves with
  resolved_via=LEGACY_IDENTITY_ALIAS.

ADAPTER
  The order/bound index remains keyed by the full (rank, value) identity in both
  the order map and _next_bounds, so a page missing one store's representation
  resumes on its own namespace.
