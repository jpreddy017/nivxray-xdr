Device Trajectory · Investigation Redesign · Final Mockup

One screen. Every region defended by an investigation question it answers. Everything the current implementation ships that doesn't serve an answer has been removed. The Bumblebee → AdaptixC2 → Akira case renders below at 1600×900 with the redesigned experience.

Every element defended · investigation question · alternative if removed

Component Investigation question it answers Why it exists (and why it wins the space it takes)
Case bar Which endpoint am I on? Is it contained? Who owns this investigation? Analyst may pivot across cases; the hostname, isolation state, and owner must be visible at all times so a mistake ("wrong endpoint") is impossible. 32 px is a hard floor — nothing shorter reads at analyst-scale.
Time compass (24-hour lens) When did the attack happen? Are there quieter or louder times to focus on? Replaces the day scrubber, hour scrubber, and mini-density row from the current implementation. Single strip carries the density sparkline, the yellow compromise time-window, red compromise dots, and the draggable viewport rectangle. Costs 56 px; would cost 130 px in the current implementation.
Attack chain sidebar What is the story? Which stages happened? Where should I start reading? The largest information upgrade. The sidebar is the table-of-contents of the attack in MITRE-tactic order. Clicking a stage focuses the canvas time-window and highlights the involved rows. This lets an analyst reconstruct the attack in ~10 seconds without touching the mouse over the canvas. Nothing in the current implementation does this.
Case summary card (sidebar tail) How bad was it? Was it stopped? Am I done? Duration · Detection mode · Containment state · Confidence. Four numbers close the loop after the analyst reads the six stages above.
Compromise indicator row (own row) What tripped the alarm? What is the indicator's name? Verbatim Cisco pattern. A compromise gets its own row with a yellow-shaded lifetime bar spanning the compromise time-window. Clicking it lights the trigger events with blue halos across all rows. Without this row, the compromise is invisible on the canvas.
Thin lifelines (1 px) What entities existed? Which are still active? Scaffolding — deliberately quiet. Only red events on a lifeline draw the eye; the line itself does not. Kills the current pill approach that colours the scaffolding.
DFS-ancestry row order + indent glyphs Who launched whom? Parent process appears above its children, indented with ├─ └─ │. Ancestry L-connectors drop from the parent lifeline to the child's first event. Zero words of copy, complete parent→child answer.
Yellow time-window column When was this endpoint under active compromise? Vertical column at 10 % opacity anchored to the compromise start/end. Never touches an entity's lifetime. Only amber use on the whole canvas.
Double-circle / single-symbol glyphs Did this entity do the thing, or was it done to? Cisco's core glyph rule. Double circle = source. Single symbol = acted upon. Applied consistently across every activity kind. Explained once in the legend, then never again.
Three-state disposition colour (green/gray/red) Is this event benign, unknown, or malicious? Fill colour is disposition, shape is activity. Two independent axes → readable at 4 px.
Blue trigger halo Which events caused this compromise to fire? Only when the analyst selects a compromise row. Every causally-linked event across all rows gets a 1.4 px blue ring. The audit trail of the indicator, without a single word.
Files / Registry / Network bands What did the attack touch outside of processes? Compact secondary bands below the process ancestry. Rendered because a ransomware incident is defined by its artifacts (lsass.dmp, *.locked, note.txt, TOR exit). Costs ~180 px in scenic; pays back with the artefact story.
Evidence pane · verbatim Cisco field list What is the technical detail of the selected event? Tabbed to Evidence by default. Fields ordered by frequency of analyst use: verdict badges → title → command line → SHA → parent → child → created → MITRE → detection → actions → note. Every field maps to a Cisco User Guide entry.
Analyst note field (Evidence pane) What did the analyst conclude, and why? Persistent shift-handoff record. Written directly into the case, retained across sessions, exported with the case bundle. The note is what makes the case reusable.
Status bar Where am I in time? How much zoom? How many selected? One row of monospace read-outs. No decoration. Always visible so the analyst never wonders "what am I looking at?"

Removed from the shipped implementation

Component removed Why analyst didn't need it What replaces its job (if anything)
Horizontal pill lifelines Coloured the scaffolding, not the events. Made every row shout equally. Thin 1-px neutral lifelines. Colour reserved for events.
Amber/yellow tint on entity rows Every row rendered "suspicious" so nothing looked suspicious. Amber is only the compromise time-window column.
Day scrubber (JUN/JUL bar) Cases live in a single day 99 % of the time; the empty months were noise. Merged into the 24-hour time compass with a lightweight date picker in the case bar.
Hour scrubber row Duplicated the compass's job at a different vertical position. Same compass carries hours + density + compromise dots + viewport rectangle.
Filter row across the top Consumed 36 px every second for a job used ~1 time per case. Slide-out drawer opened by \; five-category filter (Activity · System · Disposition · Flags · File Type).
Analyst / Expert toggle button in LeftRail A preference lived in the wrong place; analysts toggle it once and forget it. Preferences menu (⌘ ,) — analyst vs expert vs raw.
Minimap in the canvas corner Duplicated the compass; competed for the analyst's eye in the busiest area. The compass already shows the viewport rectangle over the full case.
"Training note" green pill (bottom-right) Belongs to onboarding, not to an active investigation. Moved into the case bar as a small note-count badge; opens the notes drawer on click.
Four separate Evidence / Overview / MITRE / Reference tabs Overview and Reference repeated Evidence content one field at a time. Evidence + MITRE + History + Artifacts. Four tabs, each with a unique reason to exist.
Empty white space to the right of the events cluster Was a bug of static CONTENT_W = 3000; not intentional. Canvas width is responsive; at scale 1 the timeline fills the viewport exactly.

The analyst's cognitive path across this screen

Read left → right, top → bottom, in this order:

1. Case bar. Am I on the right endpoint? Yes — FIN-DC-01, isolated.
2. Compass. When did it happen? A dense yellow-shaded 12-minute window with three red dots at 13:04.
3. Sidebar stage 01–06. What is the story? Six numbered chapters, most severe at chapter 04 (Credential Access ★) and chapter 06 (Impact ★).
4. Compromise row. ⚠ Reflective DLL Injection — the case in one row.
5. Root lifeline. explorer.exe. From it descends msiexec.exe → cmd.exe → ….
6. Red cluster. Two rows scream — rundll32.exe and powershell.exe. All red events fall inside the yellow compromise window. Blue halos mark the ones that fired the indicator.
7. Impact. locker.exe with three red circles, and the *.locked ×7 row of red plus-marks. The ransomware moment is unmistakable.
8. Network. One outbound TOR row · red arrow · 264 MB EXFIL caption.
9. Evidence pane. The selected event has full technical detail without a click on the canvas.

Total time to answer "where did this attack begin, how did it propagate, how did it end?" — under 10 seconds, no evidence-pane reading required. That is the acceptance test.
